## 1. ติดตั้ง

### แบบ binary (แนะนำ — ไม่ต้องมี .NET)

ดาวน์โหลด zip ตามเครื่องจาก [Releases](https://github.com/AeyXD/thaiwrap/releases):

| เครื่อง | ไฟล์ | ตัวโปรแกรมใน zip |
|---|---|---|
| Windows 64-bit | `thaiwrap-cli-win-x64.zip` | `ThaiWrap.Cli.exe` |
| macOS (Apple Silicon) | `thaiwrap-cli-osx-arm64.zip` | `ThaiWrap.Cli` |
| Linux 64-bit | `thaiwrap-cli-linux-x64.zip` | `ThaiWrap.Cli` |

แตก zip ไว้ที่ไหนก็ได้ — **ให้โฟลเดอร์ `data/` (มี `words_th.txt`) อยู่ข้างตัวโปรแกรมเสมอ** โปรแกรมหาพจนานุกรม
จาก `data/words_th.txt` ในโฟลเดอร์ที่รันคำสั่งก่อน ถ้าไม่มีจึงหาข้างตัวโปรแกรม (ระบุเองได้ด้วย `-w`)

```bash
# macOS / Linux
cd ~/tools/thaiwrap
chmod +x ThaiWrap.Cli                                 # ถ้าแตก zip แล้วรันไม่ได้ (Permission denied)
xattr -d com.apple.quarantine ThaiWrap.Cli            # macOS เท่านั้น: ถ้าระบบบล็อกว่าไม่รู้จักผู้พัฒนา
./ThaiWrap.Cli --help
```

```powershell
# Windows (PowerShell)
cd C:\tools\thaiwrap
.\ThaiWrap.Cli.exe --help
```

คู่มือนี้เขียนคำสั่งเป็น `thaiwrap …` เพื่อให้อ่านง่าย — แทนด้วย `./ThaiWrap.Cli` (macOS/Linux) หรือ `.\ThaiWrap.Cli.exe` (Windows)
หรือเพิ่มโฟลเดอร์โปรแกรมเข้า PATH

### แบบรันจากซอร์ส (สำหรับคนแก้โค้ด)

ต้องมี .NET SDK 10 แล้วแทน `thaiwrap` ด้วย `dotnet run --project src/ThaiWrap.Cli --`:

```bash
git clone https://github.com/AeyXD/thaiwrap && cd thaiwrap
dotnet run --project src/ThaiWrap.Cli -- samples/game_sentences.txt -m sep
```

## 2. เริ่มต้นใน 5 นาที

ลองตัดคำดูก่อน (`-m sep` แสดงรอยตัดเป็น `|` แทนการแทรกตัวมองไม่เห็น):

```bash
echo "นักเดินทางจากแดนไกลมาถึงหมู่บ้าน" | thaiwrap -m sep
# นักเดินทาง|จาก|แดน|ไกล|มาถึง|หมู่บ้าน
```

workflow ปลอดภัยกับไฟล์งานแปลจริง — **ดูก่อน เขียนทีหลัง เก็บต้นฉบับไว้เสมอ**:

```bash
# 1) ดู diff (จุดตัดแสดงเป็น ·) — ไม่เขียนอะไร
thaiwrap items.csv --columns thai --dry-run

# 2) พอใจแล้วเขียนเป็นไฟล์ใหม่ ต้นฉบับไม่ถูกแตะ
thaiwrap items.csv --columns thai -o items.th.csv

# 3) ทั้งโฟลเดอร์: สร้าง <ชื่อ>.zwsp.<ext> ข้างไฟล์เดิม
thaiwrap translations/ -r --dry-run
thaiwrap translations/ -r
```

ถ้ายังไม่แน่ใจว่าเกมใช้ตัวคั่นแบบไหน อ่านหัวข้อ 3 ก่อน — ตัวคั่นผิดชนิด = เกมไม่ตัดบรรทัดให้

## 3. เลือกตัวคั่นให้ตรงกับเอนจิน

| เกม / เอนจิน | ใช้ | หมายเหตุ |
|---|---|---|
| Unity (TextMeshPro / UGUI), Ren'Py, เอนจินส่วนใหญ่ | default (ZWSP U+200B) | ไม่ต้องใส่อะไร |
| Scaleform/Flash (เช่น The Witcher 3) | `--break-char hairspace` (U+200A) | Scaleform ไม่นับ ZWSP เป็นจุดตัด · ฟอนต์ต้องมี glyph ว่างที่ U+200A |
| เอนจินที่ตัดเฉพาะช่องว่างจริง (Aurora เช่น The Witcher 1) | `--break-char space` | เว้นช่องว่างจริงแบบกลุ่มวลี — อ่านข้อควรระวังด้านล่าง |
| Godot 4 | ไม่จำเป็น | ตัดไทยเองได้แล้ว (ใช้ก็ไม่เสียหาย) |
| RPG Maker MZ | ใช้ไม่ได้ | ตัดระดับตัวอักษร — ต้องแก้ที่ plugin ตัดบรรทัดของเกม |

หลักฐานและเทคนิคฟอนต์ทั้งหมด: [COMPATIBILITY.md](COMPATIBILITY.md)

**โหมด `--break-char space`** — เว้นทุกคำจะอ่านเป็น "เว้น วรรค ทุก คำ" โปรแกรมจึงรวมคำเป็นกลุ่มวลีตามกฎผูกคำไทย
(ไม่เว้นหลัง ผู้/การ/ใน/ไม่ ไม่เว้นก่อน ได้/แล้ว/ไป) แล้วเว้นเฉพาะรอยต่อกลุ่ม:

```
นักผจญเหตุการณ์วิเศษพาเพื่อนๆเดินทางข้ามป่าลึกเพื่อตามหาสมบัติโบราณที่สาบสูญมานานหลายร้อยปี
→ นักผจญ เหตุการณ์ วิเศษพา เพื่อนๆเดิน ทางข้ามป่าลึก เพื่อตามหา สมบัติโบราณ ที่สาบสูญมา นานหลายร้อยปี
```

- `--chunk <n>` ความยาวกลุ่มสูงสุด (default ของโหมดนี้ 12) · `--min-len <n>` ไม่แตะข้อความที่ทุกบรรทัดสั้นกว่า N ตัวอักษรไทย
  (default 40 — กัน "เกม ใหม่" กลางป้ายเมนู) · ใส่ `0` เพื่อปิด
- ⚠️ **รันซ้ำไม่ได้** — ช่องว่างที่แทรกแยกจากช่องว่างที่ทีมแปลพิมพ์ไม่ได้ รันบนไฟล์ที่แปลงแล้วจะเว้นเพิ่มอีก
  ต้องรันจากต้นฉบับสะอาดทุกครั้ง (ตัวคั่นแบบอื่นรันซ้ำได้ผลเดิม)

## 4. ไฟล์เข้า–ออก: ไฟล์เดียว · โฟลเดอร์ · stdin

| อินพุต | ผลลัพธ์ default | ตัวเลือกที่เกี่ยว |
|---|---|---|
| ไฟล์เดียว | พิมพ์ออกหน้าจอ (stdout) | `-o <ไฟล์>` เขียนลงไฟล์ · `--dry-run` ดู diff |
| โฟลเดอร์ | สร้าง `<ชื่อ>.zwsp.<ext>` ข้างไฟล์เดิม (เฉพาะไฟล์ที่เปลี่ยน) | `-r` ลงโฟลเดอร์ย่อย · `--inplace` เขียนทับ + สำรอง `.bak` |
| ไม่ระบุ (stdin) | stdout — ถือเป็นข้อความเปล่าเสมอ | ใช้ต่อท่อกับเครื่องมืออื่น |

- โหมดโฟลเดอร์อ่านเฉพาะ `.csv .tsv .json .po .pot .txt` และข้ามไฟล์ `*.zwsp.*` กับ `*.bak` (ผลของรอบก่อน)
- `--inplace` สร้าง `.bak` ครั้งแรกเท่านั้น รันซ้ำไม่ทับไฟล์สำรอง จึงเก็บต้นฉบับแท้ไว้เสมอ ·
  **ใช้ได้กับโหมดโฟลเดอร์เท่านั้น** — ไฟล์เดียวใช้ `-o` แทน (อย่าตั้ง `-o` เป็นชื่อเดียวกับไฟล์ต้นทาง เพราะไม่มีสำรอง)
- ไฟล์ output ใช้การเข้ารหัสและ BOM เดียวกับไฟล์เข้า · ส่วนที่ไม่ได้แปลงคงเดิมทุกไบต์ (CRLF/LF, quote ใน CSV, ลำดับ key JSON, คอมเมนต์ .po)
- **การเข้ารหัส**: อ่าน UTF-8 (มี/ไม่มี BOM) และ UTF-16 ที่มี BOM · ไฟล์ภาษาไทยแบบเก่า (CP874/TIS-620) หรือไฟล์ที่ข้อมูลเสีย
  ถูกปฏิเสธด้วย exit 2 ไม่เขียนอะไร — แปลงเป็น UTF-8 ก่อน (ดูหัวข้อ 12)

## 5. ฟอร์แมตไฟล์และการเลือกข้อความที่จะแปลง

ฟอร์แมตเดาจากนามสกุล (`-f auto`) หรือระบุเอง `-f text|csv|tsv|json|po|keyvalue`

| ฟอร์แมต | แปลงอะไร | ไม่แตะ | เลือกเฉพาะส่วน |
|---|---|---|---|
| **csv / tsv** | ทุกเซลล์ (default) | — | `--columns` |
| **json** | ทุก string ที่เป็น value | key ทุกตัว · ตัวเลข/โครงสร้าง | `--json-keys` · `--json-path` |
| **po / pot** | `msgstr` | `msgid` · header · รายการเก่า `#~` · คอมเมนต์ | — |
| **keyvalue** (XUnity.AutoTranslator) | ค่าหลัง `=` | key · บรรทัด `#` | — ต้องสั่ง `-f keyvalue` (นามสกุล .txt จะถูกอ่านเป็นข้อความเปล่า) |
| **text** | ทุกบรรทัด | ตัวจบบรรทัด | — |

ข้อความที่ไม่มีอักษรไทยไม่ถูกเปลี่ยนอยู่แล้ว แต่ควรเลือกคอลัมน์/field ให้ชัดเมื่อมีรหัสหรือข้อความที่ห้ามแตะปนอยู่

### csv/tsv — `--columns`

```bash
thaiwrap items.csv --columns thai --dry-run        # ตามชื่อ header → ข้ามแถว header ให้
thaiwrap items.csv --columns "3,4" --dry-run       # ตามเลขคอลัมน์ (เริ่ม 1) → ทุกแถวรวมแถวแรก
```

เลขคอลัมน์ที่เกินจำนวนคอลัมน์ของไฟล์ (นับจากแถวที่กว้างที่สุด) หรือชื่อที่ไม่มีใน header = exit 2 พร้อมบอกว่าไฟล์ไหนมีกี่คอลัมน์
**[หลัง v0.12.1]** (ก่อนหน้านี้เลขเกินถูกข้ามเงียบ ๆ — ไม่แปลงอะไรและ `--check`/`--placeholders` ผ่านโดยไม่ได้ตรวจ) ·
แถวที่สั้นกว่าคอลัมน์ที่เลือกยังข้ามได้ตามปกติ · โหมดโฟลเดอร์หยุดที่ไฟล์ที่ไม่เข้ากัน ไฟล์ก่อนหน้าเขียนไปแล้ว — ใช้ `--dry-run` ก่อน

ตัวคั่น csv เดาจากบรรทัดแรก (`,` `;` หรือแท็บ) · เซลล์หลายบรรทัดใน `"…"` รองรับตาม RFC 4180

### json — `--json-keys` และ `--json-path`

```bash
thaiwrap dialogs.json --json-keys "desc,tooltip"                 # value ใต้ key ชื่อนี้ ทุกระดับ
thaiwrap items.json --json-path "/items/*/desc"                  # ตามตำแหน่ง   [หลัง v0.12.1]
thaiwrap ui.json --json-path "/menu.start,/dialogs/**/text"      # หลาย path คั่นด้วย ,
```

- `--json-keys`: ใช้ชื่อ key ที่ครอบ value โดยตรง (value ใน array ใช้ชื่อ key ของ array นั้น เช่น `{"lines":["…"]}` → `lines`)
- `--json-path` เขียนแบบ JSON Pointer: segment คั่นด้วย `/` · index ของ array เริ่ม 0 (`/items/0/name`) ·
  `*` = key/index ใดก็ได้หนึ่งชั้น · `**` = กี่ชั้นก็ได้ (รวมศูนย์ชั้น) · key ที่มีจุดเขียนตรง ๆ (`/menu.start`) ·
  key ที่มี `/` เขียน `~1` และ `~` เขียน `~0`
- ใช้คู่กันได้ — value ที่ตรงตัวใดตัวหนึ่งถูกแปลง · ใช้ `--json-path` เมื่อ key ชื่อเดียวกันมีทั้งข้อความและรหัส

## 6. ไฟล์ของโปรเจกต์: words_extra · nobreak · check_allow

ไฟล์ข้อความธรรมดา (UTF-8 · บรรทัดละรายการ · `#` = คอมเมนต์) ที่โปรแกรมหยิบใช้เอง **ไม่ต้องใส่ตัวเลือก** —
ใช้ไฟล์แรกที่เจอตามลำดับ:

1. `data/<ชื่อไฟล์>` ใต้โฟลเดอร์ที่รันคำสั่ง
2. `<ชื่อไฟล์>` ในโฟลเดอร์ที่รันคำสั่ง
3. ข้าง `words_th.txt` ที่ใช้อยู่ (ปลั๊กอินหาที่นี่ที่เดียว: `BepInEx/plugins/ThaiWrap/`)
4. ข้างตัวโปรแกรม — ใน `data/` และโฟลเดอร์เดียวกับโปรแกรม

เมื่อโหลดได้ โปรแกรมพิมพ์ตำแหน่งและจำนวนรายการให้เห็นทุกครั้ง — ถ้าไม่เห็นบรรทัดนั้น แปลว่าไม่ได้ใช้ไฟล์

### `words_extra.txt` — คำเฉพาะเกม

```text
# ชื่อตัวละคร / สถานที่ / ศัพท์เกม
เฟรย่า
เคียร์มอร์เฮน
-ใช้การ           ← ขึ้นต้น - = ลบคำออกจากพจนานุกรม
```

การลบคำสำคัญเท่าการเพิ่ม: บางคำในพจนานุกรม "แย่งพยางค์" คำถัดไป เช่น `ใช้การเล่น` ถูกตัด `ใช้การ|เล่น` —
ลบ `ใช้การ` แล้วได้ `ใช้|การ|เล่น` · หาคำที่ควรเพิ่มจาก `--stats` ส่วน "คำนอกพจนานุกรมที่พบบ่อย" (หัวข้อ 8)

### `nobreak.txt` — วลีห้ามตัดกลางวลี

```text
เดอะ วิทเชอร์
อาร์ยัน ลา วาเล็ตต์
```

ช่องว่างกลางวลีกลายเป็น NBSP (U+00A0 — กว้างเท่าช่องว่างแต่ไม่เป็นจุดตัด) และไม่มีจุดตัดใดภายในวลี ·
วลีซ้อนกันเลือกวลียาวก่อน · รันซ้ำได้ผลเดิม · ฟอนต์ของเกมต้องมี glyph ที่ U+00A0 ·
เขียนวลีด้วยตัวสะกดที่ถูก (จับหลัง `--normalize`) · เอนจินที่ตัดเฉพาะ U+0020 + ฟอนต์ช่องว่างกว้าง 0 ต้องใช้วิธีอื่น
([COMPATIBILITY.md](COMPATIBILITY.md))

### `check_allow.txt` — ข้อยกเว้นของตัวตรวจคำผิด (`--stats`)

```text
# ใส่ที่มาทุกบรรทัด (id / บริบท / ต้นฉบับ)
วิลโลว์           ← ไม่รายงานรูปนี้เลย (ชื่อตัวละคร Willow)
ได้[ลับ]มีด        ← ไม่รายงาน "ลับ" เฉพาะในวลีนี้
ม้า>มา            ← ไม่เสนอ มา แทน ม้า
```

## 7. ตัวเลือกที่แก้ตัวอักษร: --normalize · --yamok-nbsp

ปิดไว้เป็น default ทั้งคู่ เพราะ**เปลี่ยนตัวอักษรของผู้แปลจริง** (การลบจุดตัดออกจะไม่ได้ต้นฉบับคืน) — ดู `--dry-run` ก่อนเสมอ

**`--normalize`** ยุบรูปพิมพ์ผิดที่ editor/Excel แสดงเหมือนถูก แต่ทำให้ตัดคำเพี้ยนทั้งย่อหน้า:

```
ก่อน:  สวัั·สดี·เป็็็น·ทาส       หลัง:  สวัสดี·เป็น·ทาส
```

แก้เฉพาะรูปที่มีทางแก้ทางเดียว: `เเ→แ` · สระ/วรรณยุกต์ซ้อน · ลำดับมาร์คผิด (`มาท่ีนี่`) · `นํ้า→น้ำ` · วรรณยุกต์หลงหลังสระหน้า
(`ไ่ม่→ไม่`) · รูปกำกวม (สระต่างตัวซ้อน) ไม่แก้ แต่เตือนใน `--stats` · ไม่แตะเสียงลากอย่าง `อาาา` และไม่แตะ placeholder/แท็ก

**`--yamok-nbsp`** สำหรับงานที่เว้นวรรคหน้าไม้ยมก (`ต่าง ๆ`): ช่องว่างหน้า ๆ เป็นจุดตัดของเอนจิน บรรทัดใหม่จึงขึ้นต้นด้วย ๆ ได้ —
ตัวเลือกนี้เปลี่ยนช่องว่างนั้นเป็น NBSP (ช่องว่างหลัง ๆ ยังเป็นจุดตัด) · ฟอนต์ต้องวาด U+00A0 กว้างเท่าช่องว่าง

## 8. โหมดตรวจ (QA): --check · --placeholders · --mispaste · --stats

| โหมด | ตรวจอะไร | เขียนไฟล์ | exit code | ต้องใช้พจนานุกรม |
|---|---|---|---|---|
| `--check` | ข้อความไทยที่ยังไม่ถูกแทรกจุดตัด | ไม่ | 1 ถ้าพบ | ใช้ |
| `--placeholders` | `{0}` `%s` `<tag>` ในคำแปลเทียบต้นฉบับ | ไม่ | 1 ถ้าพบ | ไม่ใช้ |
| `--mispaste` | คำแปลที่น่าจะวางผิดแถว (csv/tsv ไฟล์เดียว) | ไม่ | 0 เสมอ (ข้อเสนอ) | ไม่ใช้ |
| `--stats` | คำนอกพจนานุกรม · รูปพิมพ์ผิด · คำผิดตามบริบท | ตามปกติ — คู่ `--dry-run` = ไม่เขียน | ตามปกติ | ใช้ |

ทุกโหมดพิมพ์รายงานทาง stderr · ผลของ `--mispaste` และข้อเสนอใน `--stats` **เป็นข้อเสนอ** ตรวจด้วยตาแล้วแก้ที่ไฟล์ต้นทางเอง

### `--check` — กันไฟล์ที่ยังไม่แปลงหลุดเข้าเกม

```bash
thaiwrap translations/ -r --check ; echo $?
# ยังไม่ถูกแตรป: translations/quest.csv
# ตรวจไม่ผ่าน: 1/12 ไฟล์ยังมีข้อความไทยไม่ถูกแตรป   → exit 1
```

ใช้ตัวเลือกชุดเดียวกับตอนแปลงจริง (`--columns` `--break-char` ฯลฯ) ไม่งั้นผลตรวจจะไม่ตรง

### `--placeholders` — placeholder/แท็กในคำแปลต้องเหมือนต้นฉบับ

```bash
thaiwrap translations/ -r --placeholders ; echo $?
```

```
  items.csv แถว 3 — หาย {0} · เกิน {gold}
    EN: You found {0} gold
    TH: คุณพบทอง {gold} เหรียญ
```

- นับ `<…>` · `{…}` ที่หน้าตาเป็น placeholder (`{0}` `{name}` `{0:N2}`) · printf (`%s %d %1$s %.2f %@`)
- **ไม่นับ** `<br>` (ทีมแปลเพิ่ม/ลดบรรทัดได้) · `{…}` ที่เป็นถ้อยคำ (มีช่องว่าง/อักษรไทย) · `[…]` · `%%`
- สลับตำแหน่งได้ (`{1} … {0}`) ยกเว้น printf ไม่ระบุตำแหน่ง (`%s %d`) ต้องเรียงตามต้นฉบับ — ถ้าต้องสลับให้ใช้ `%1$s %2$d` ·
  แท็กต้องไม่ปิดข้ามชั้น (`<b><i>…</b></i>`)
- หาต้นฉบับจาก: csv/tsv = เซลล์อังกฤษที่ดูเป็นถ้อยคำ (หรือคอลัมน์ที่ระบุ — ด้านล่าง) · po = `msgid` · `-f keyvalue` = key ·
  json/text ไม่มีต้นฉบับในไฟล์จึงข้าม · ข้อความที่มี placeholder แต่หาต้นฉบับไม่ได้รายงานเป็นจำนวน "ตรวจไม่ได้"

### ระบุคอลัมน์ต้นฉบับ/คำแปลเอง — `--source-column` **[หลัง v0.12.1]**

`--placeholders` `--stats` `--mispaste` เดาเองว่าเซลล์ไทยมากสุดคือคำแปล และเซลล์อังกฤษมากสุดคือต้นฉบับ — พลาดได้เมื่อตารางมี
คอลัมน์หมายเหตุอังกฤษยาวกว่าต้นฉบับ หรือมีคำแปลหลายคอลัมน์:

```bash
thaiwrap items.csv --placeholders --source-column en --columns th
thaiwrap items.csv --placeholders --source-column 2 --columns "4,5"
```

- `--columns` ในโหมดตรวจ = คอลัมน์คำแปล — ตรวจทุกเซลล์ที่ไม่ว่าง แม้ไม่มีอักษรไทย · `--mispaste` ใช้คอลัมน์แรกที่มีข้อความ
- `--source-column` = คอลัมน์ต้นฉบับเดียว ใช้ค่าตรง ๆ ไม่กรอง · เซลล์ว่าง = ไม่มีต้นฉบับ (ไม่เดาแทน)
- ใช้ชื่อ = ข้ามแถว header · ไม่พบชื่อ / เลขเกินตาราง / ซ้ำกับคอลัมน์คำแปล = exit 2 · ระบุฝั่งเดียวได้ อีกฝั่งเดาเอง

### `--mispaste` — คำแปลวางผิดแถว

ทีมแปล copy คำแปลของแถวอื่นมาวาง ทำให้คำแปลไม่ตรงต้นฉบับโดยไม่มีใครเห็น — ตรวจสองเกณฑ์:
ไทยยาว ≥40 ตัวซ้ำกันหลายแถวแต่อังกฤษเป็นคนละเรื่อง · ความยาวไทย/อังกฤษผิดสัดส่วน (นอก 0.2–3.5 เท่า)

```bash
thaiwrap quests.csv --mispaste
```

### `--stats` — สถิติและข้อเสนอแก้คำ

```bash
thaiwrap translations/ -r --stats --dry-run      # รายงานอย่างเดียว ไม่เขียนไฟล์
```

ใช้คู่การแปลงจริงหรือ `--check` ก็ได้ — รายงานเหมือนกัน (ก่อนหน้า **[หลัง v0.12.1]** คู่ `--dry-run`/`--check` จะไม่มีรายงานส่วนนี้)

ท้ายรายงานมี:

- **รูปพิมพ์ผิด** ที่ `--normalize` แก้ได้ และรูปกำกวมที่ต้องตรวจด้วยตา
- **คำนอกพจนานุกรมที่พบบ่อย** (≥2 ครั้ง) — คัดคำจริงไปใส่ `words_extra.txt`
- **คำที่น่าจะพิมพ์สลับ ร↔ล / สะกดผิด** เช่น บุกลุก → บุกรุก · ตลอดการเลย → ตลอดกาล
- **คำที่สะกดถูกแต่ผิดบริบท** (ขา/ข้า · เข่า/เข้า · การ/กาล) ตัดสินจากสถิติคู่คำของทุกไฟล์ในรอบนั้น —
  ยิ่งตรวจทั้งโฟลเดอร์ยิ่งแม่น ไฟล์เล็กไฟล์เดียวแทบไม่มีผล
- ถ้ามีต้นฉบับอังกฤษคู่กัน (csv/tsv · po · keyvalue) จะตัดข้อเสนอที่ต้นฉบับยืนยันว่าคำเดิมถูก
  (`รุกขึ้นเหนือ` + *push north* → ไม่เสนอ ลุกขึ้น)

รูปที่ตรวจแล้วว่าถูก ใส่ `check_allow.txt` (หัวข้อ 6) เพื่อไม่ให้ขึ้นซ้ำ

## 9. สูตรตามงาน

**เกม Unity + ไฟล์ csv ที่มีคอลัมน์ ID / en / th**

```bash
thaiwrap loc/ -r --columns th --dry-run
thaiwrap loc/ -r --columns th --inplace          # เขียนทับ + .bak
thaiwrap loc/ -r --columns th --check            # ใส่ใน CI
```

**ซับ Scaleform (แบบ Witcher 3) ที่เว้นวรรคหน้าไม้ยมก**

```bash
thaiwrap subs/ -r --break-char hairspace --yamok-nbsp --normalize --dry-run
```

**XUnity.AutoTranslator (`_AutoGeneratedTranslations.txt`)**

```bash
thaiwrap _AutoGeneratedTranslations.txt -f keyvalue -o _AutoGeneratedTranslations.th.txt
thaiwrap _AutoGeneratedTranslations.txt -f keyvalue --placeholders
```

**gettext (.po)**

```bash
thaiwrap locale/th/LC_MESSAGES/ -r --dry-run
thaiwrap locale/th/LC_MESSAGES/ -r --placeholders
```

**ตรวจไฟล์แปลใน GitHub Actions** (ให้ PR ไม่ผ่านถ้า placeholder พังหรือมีไฟล์ยังไม่แปลง):

```yaml
jobs:
  thai-qa:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: ดาวน์โหลด thaiwrap
        run: |
          curl -sL -o tw.zip https://github.com/AeyXD/thaiwrap/releases/latest/download/thaiwrap-cli-linux-x64.zip
          mkdir tw && unzip -q tw.zip -d tw && chmod +x tw/ThaiWrap.Cli
      - run: tw/ThaiWrap.Cli loc/ -r --placeholders
      - run: tw/ThaiWrap.Cli loc/ -r --columns th --check
```

**ลบจุดตัดออก (ย้อนกลับ)** — ใช้ไฟล์ `.bak` หรือต้นฉบับจะดีที่สุด · ถ้าไม่มี ลบตัวคั่นที่แทรกได้ (ใช้ได้เฉพาะ ZWSP/hairspace
และเมื่อไม่ได้เปิด `--normalize`/`--yamok-nbsp`/`nobreak.txt`):

```bash
perl -CSD -pi -e 's/\x{200B}//g' file.csv      # ZWSP — hairspace ใช้ \x{200A}
```

## 10. ตารางตัวเลือกทั้งหมด และ exit code

| ตัวเลือก | ค่า | ความหมาย |
|---|---|---|
| `-o`, `--out` | ไฟล์ | เขียนผลลงไฟล์ (ไฟล์เดียว) — default stdout |
| `-w`, `--words` | ไฟล์ | พจนานุกรม — default `data/words_th.txt` |
| `-m`, `--mode` | `zwsp` \| `sep` | `sep` แสดงรอยตัดเป็น `\|` ไว้ดูผล |
| `-f`, `--format` | `auto` `text` `csv` `tsv` `json` `po` `keyvalue` | ฟอร์แมตไฟล์ — default เดาจากนามสกุล |
| `--columns` | `"1,3"` หรือ `"ชื่อ"` | csv/tsv: คอลัมน์ที่แปลง (และคอลัมน์คำแปลของโหมดตรวจ) |
| `--source-column` | เลขหรือชื่อ | csv/tsv: คอลัมน์ต้นฉบับของโหมดตรวจ **[หลัง v0.12.1]** |
| `--json-keys` | `"desc,tooltip"` | json: แปลงเฉพาะ value ใต้ key ชื่อเหล่านี้ |
| `--json-path` | `"/items/*/desc"` | json: แปลงเฉพาะ value ตาม path **[หลัง v0.12.1]** |
| `--break-char` | `zwsp` `hairspace` `space` | ชนิดตัวคั่น (หัวข้อ 3) |
| `--chunk` | n | รวมคำเป็นกลุ่ม ≤ n ตัวอักษร (0 = ทุกรอยคำ · space default 12) |
| `--min-len` | n | ไม่แตะข้อความสั้นกว่า n ตัวอักษรไทย (space default 40) |
| `--dry-run` | — | แสดง diff ไม่เขียนไฟล์ |
| `--max-diff` | n | จำนวนบรรทัด diff สูงสุด (default 40) |
| `-r`, `--recursive` | — | โหมดโฟลเดอร์: ลงโฟลเดอร์ย่อย |
| `--inplace` | — | โหมดโฟลเดอร์: เขียนทับ + `.bak` |
| `--normalize` | — | ยุบรูปพิมพ์ผิดก่อนตัดคำ (หัวข้อ 7) |
| `--yamok-nbsp` | — | ช่องว่างหน้า ๆ → NBSP (หัวข้อ 7) |
| `--maxword` | n | ความยาวคำสูงสุดจากพจนานุกรม (0 = ไม่จำกัด) |
| `--unknown-threshold` | n | คำนอกพจนานุกรมยาวกว่า n cluster จึงยอมให้ตัด (default 8) |
| `--check` | — | lint: exit 1 ถ้ายังมีไทยไม่ถูกแปลง |
| `--placeholders` | — | ตรวจ placeholder/แท็กเทียบต้นฉบับ |
| `--mispaste` | — | ตรวจคำแปลวางผิดแถว (csv/tsv) |
| `--stats` | — | สถิติ + ข้อเสนอแก้คำ |
| `-h`, `--help` | — | แสดงวิธีใช้ |

| exit code | ความหมาย |
|---|---|
| 0 | สำเร็จ / ตรวจผ่าน |
| 1 | `--check` หรือ `--placeholders` พบปัญหา |
| 2 | ใช้ผิด (ตัวเลือก/ค่าผิด · ไม่พบคอลัมน์หรือเลขคอลัมน์เกินตาราง) · หาไฟล์/พจนานุกรมไม่เจอ · การเข้ารหัสไฟล์ผิด — ไม่มีการเขียนไฟล์ |

## 11. ปลั๊กอิน BepInEx (Unity)

สำหรับเกม Unity (Mono) ที่ติด BepInEx 5 — ตัดคำตอนข้อความแสดงบนจอ ไม่ต้องแก้ไฟล์ล่วงหน้า

2. ดาวน์โหลด `ThaiWrap-BepInEx.zip` จาก [Releases](https://github.com/AeyXD/thaiwrap/releases) แตกลง `<โฟลเดอร์เกม>/BepInEx/plugins/`

3. เปิดเกมหนึ่งครั้ง แล้วปรับค่าได้ที่ `BepInEx/config/thaiwrap.plugin.cfg` (เปิด/ปิด · `Normalize` · `YamokNbsp` ·
   `MaxWordLength` · `UnknownBreakThreshold`)
4. `words_extra.txt` และ `nobreak.txt` วางใน `BepInEx/plugins/ThaiWrap/`

รองรับ TextMeshPro และ UGUI Text · ⚠️ **ยังไม่ได้ทดสอบในเกมจริง** (แผนทดสอบ: [PLUGIN-TEST-PLAN.md](PLUGIN-TEST-PLAN.md)) ·
ยังไม่รองรับเกม IL2CPP · ถ้าลองแล้วได้ผลอย่างไร แจ้งที่ [Issues](https://github.com/AeyXD/thaiwrap/issues) ได้เลย

## 12. แก้ปัญหา / คำถามที่พบบ่อย

**"ไม่พบ word list"** — โฟลเดอร์ `data/` ไม่ได้อยู่ข้างตัวโปรแกรม หรือย้ายไฟล์โปรแกรมออกมาคนเดียว ·
แก้: วาง `data/words_th.txt` ข้างโปรแกรม หรือระบุ `-w /path/to/words_th.txt`

**ไฟล์ถูกปฏิเสธเรื่องการเข้ารหัส (exit 2)** — ไฟล์เป็น CP874/TIS-620 (ไทยแบบเก่า) หรือข้อมูลเสีย ·
แปลงเป็น UTF-8 ก่อน แล้วตรวจว่าภาษาไทยอ่านออก:

```bash
iconv -f CP874 -t UTF-8 old.txt > new.txt          # macOS / Linux
```

(Windows: เปิดด้วย Notepad → Save As → Encoding: UTF-8) · โปรแกรมไม่แปลงให้เองเพราะเดาการเข้ารหัสผิดจะทำให้ข้อความเสียเงียบ ๆ

**ข้อความไทยในหน้าต่าง cmd เป็นตัวต่างดาว** — เป็นเรื่องการแสดงผลของ console เท่านั้น ไฟล์ที่เขียนถูกต้อง ·
สั่ง `chcp 65001` ก่อน หรือใช้ Windows Terminal / PowerShell รุ่นใหม่

**เปิด csv ใน Excel แล้วไทยเพี้ยน / เซฟแล้วพัง** — Excel เดาการเข้ารหัสของ csv ที่ไม่มี BOM ผิด ·
นำเข้าผ่าน Data → From Text/CSV เลือก UTF-8 และเซฟเป็น "CSV UTF-8" · ตัวคั่นที่แทรกมองไม่เห็นใน Excel เป็นเรื่องปกติ

**เกมแสดงสี่เหลี่ยม/ช่องว่างแปลก ๆ ตรงรอยคำ** — ฟอนต์ไม่มี glyph ของตัวคั่น (พบบ่อยกับ hairspace และ NBSP) ·
เติม glyph ว่างให้ฟอนต์ตาม [COMPATIBILITY.md](COMPATIBILITY.md) หรือเปลี่ยนชนิดตัวคั่น

**เกมยังตัดกลางคำ / ไม่ตัดบรรทัดเลย** — ตัวคั่นไม่ตรงเอนจิน (หัวข้อ 3) · ลอง `-m sep` ดูว่าตัดคำตรงไหน ·
ถ้าตัดคำผิดเพราะชื่อเฉพาะหรือคำแย่งพยางค์ แก้ด้วย `words_extra.txt` · ถ้าตัวพิมพ์ผิด (`เเ` `นํ้า`) ใช้ `--normalize`

**ชื่อตัวละครถูกตัดครึ่ง** — ใส่ชื่อใน `words_extra.txt` · ชื่อที่มีช่องว่างกลางชื่อใส่ `nobreak.txt`

**รันซ้ำบนไฟล์ที่แปลงแล้วได้ไหม** — ได้ ผลเหมือนเดิม (ยกเว้น `--break-char space` — หัวข้อ 3)

**placeholder `{name}` / แท็ก `<color>` ถูกแทรกจุดตัดไหม** — ไม่ ทุกส่วนควบคุมใน `{…}` `<…>` และ printf ถูกปกป้องทั้งก้อน
แม้ข้างในเป็นภาษาไทย

**`--inplace` กับไฟล์เดียวไม่เขียนทับ** — ตั้งใจ: `--inplace` ใช้กับโฟลเดอร์ ไฟล์เดียวให้ใช้ `-o`
