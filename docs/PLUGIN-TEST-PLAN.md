# แผนทดสอบ BepInEx Plugin ในเกม Unity จริง

สถานะ: **ยังไม่ได้ทดสอบ** — เอกสารนี้เตรียมไว้ล่วงหน้าเพื่อรันครั้งแรกให้ครบชุดและเก็บผลเป็นหลักฐาน
(อ้างใน Release notes ว่า "ยังไม่ได้ทดสอบในเกมจริง" — เมื่อตารางผลด้านล่างผ่าน จะถูกแทนที่)

เป้าหมาย: พิสูจน์ว่า `ThaiWrap.BepInEx.dll` (v0.8.0) ติดตั้งบนเกม Unity **Mono** จริงแล้ว
โหลดได้ · hook ข้อความได้ · ตัดบรรทัดไทยถูกจุด · ไม่พังอะไรตามมา

## สิ่งที่ต้องมี

| สิ่งของ | หมายเหตุ |
|---|---|
| เกม Unity ที่ runtime เป็น **Mono** (ไม่ใช่ IL2CPP) | วิธีเช็ค: ในโฟลเดอร์ `<เกม>_Data/` มี `Managed/` ที่มี `Assembly-CSharp.dll` = Mono · ถ้ามีโฟลเดอร์ `il2cpp_data` = IL2CPP (ยังไม่รองรับ — เลือกเกมอื่น) |
| BepInEx 5 (x64 หรือ x86 ตามเกม) | https://github.com/BepInEx/BepInEx/releases · แตกทับโฟลเดอร์เกม แล้วเปิดเกมครั้งหนึ่งให้สร้างโฟลเดอร์ |
| `ThaiWrap-BepInEx.zip` | จาก [Release v0.8.0](https://github.com/AeyXD/thaiwrap/releases/tag/v0.8.0) |
| จุดแสดงข้อความไทยในเกม | เกมที่มีม็อด/ระบบแปลไทย หรือช่องพิมพ์ชื่อตัวละคร หรือไฟล์ข้อความที่แก้ได้ (เช่น `StreamingAssets/*.json`) |

## ขั้นตอนเตรียม

1. ติดตั้ง BepInEx 5 ลงเกม แล้วเปิดเกมครั้งหนึ่งให้สร้างโฟลเดอร์ `BepInEx/`
2. คัดลอกโฟลเดอร์ `ThaiWrap/` ทั้งโฟลเดอร์ (DLL + words_th.txt) ไปที่ `<เกม>/BepInEx/plugins/`
3. (ถ้ามี `words_extra.txt` ของโปรเจกต์นั้น — วางข้าง `words_th.txt` ได้เลย)
4. โหมด default คือ ZWSP ไม่ต้องตั้งค่าอะไรเพิ่ม (เกม TMP/UGUI ส่วนใหญ่ใช้ได้)
5. เปิด BepInEx console ได้โดยแก้ `BepInEx/config/BepInEx.cfg` → `[Logging.Disk]` เปิด
   `LogConsole` หรือดู `BepInEx/LogOutput.log` หลังปิดเกม

## Checklist การทดสอบ

### ก. การโหลดและ hook

| # | รายการ | วิธีตรวจ |
|---|---|---|
| ก1 | plugin โหลด + พจนานุกรมครบ | ใน log มีข้อความ `โหลดพจนานุกรม 65,758 คำ` (หรือมากกว่าถ้ามี words_extra) |
| ก2 | hook สำเร็จอย่างน้อย 1 ตำแหน่ง | log มี `hook สำเร็จ N ตำแหน่ง (TMP/UGUI ที่พบในเกมนี้)` และ N ≥ 1 |
| ก3 | ไม่มี error แดงจาก ThaiWrap | log ไม่มี ` ThaiWrap` ระดับ Error/Exception |

### ข. ตัดบรรทัดภาษาไทยจริง

| # | รายการ | วิธีตรวจ |
|---|---|---|
| ข1 | ข้อความไทยยาวตัดที่รอยคำ | ภาพหน้าจอก่อน (Enabled=false) vs หลัง — บรรทัดไม่ล้นกรอบและไม่ตัดกลางคำ |
| ข2 | ไม่ตัดกลางสระ/วรรณยุกต์/ไม้ยมก | อ่านข้อความที่ตัดแล้วทุกบรรทัด — ไม่มีสระลอยนำบรรทัด |
| ข3 | ตัวเลข/อังกฤษ (เช่น `150/200`, `EXP`) คงเป็นก้อนเดียว | ดูในฉากที่มีข้อความผสม |

### ค. ความปลอดภัยระดับ runtime (จุดที่ CLI ทำไม่ได้ — สำคัญสุดของการทดสอบรอบนี้)

| # | รายการ | วิธีตรวจ |
|---|---|---|
| ค1 | placeholder ที่เกมแทนค่าจริง ยังแทนถูก | ข้อความที่มี `{…}` (ชื่อผู้เล่น/ตัวเลข) แสดง**ค่าที่แทนแล้ว** ไม่โผล่เป็นข้อความดิบ/ไม่หาย |
| ค2 | แท็ก rich-text ยังทำงาน | `<color=red>…</color>` ยังเปลี่ยนสี · `<b>` ยังหนา |
| ค3 | ไม่มี glyph แปลก (tofu/กล่อง) ที่ตำแหน่ง ZWSP | ดูหน้าจอ — ถ้าฟอนต์เกมไม่มี glyph ZWSP อาจต้อง patch ฟอนต์ (`tools/font_zwsp_patch.py`) — จดไว้เป็นข้อสังเกต ไม่ถือว่า plugin พัง |

### ง. idempotent + cache

| # | รายการ | วิธีตรวจ |
|---|---|---|
| ง1 | ข้อความเดิมแสดงซ้ำหลายครั้ง ผลเหมือนเดิม | เปิด-ปิดหน้าต่างสนทนา/เมนูเดิมซ้ำ 5+ ครั้ง |
| ง2 | ปิด-เปิดเกมซ้ำ 3 รอบ ผลคงเส้นคงวา | ปิดเกม เปิดใหม่ ดูฉากเดิม |
| ง3 | typewriter/ข้อความไหลเข้าทีละส่วนไม่พังกลางทาง | ฉากที่ข้อความค่อยๆ พิมพ์ (ถ้าเกมมี) |

### จ. parity กับ CLI (ผลเกม = ผล CLI บนข้อความเดียวกัน)

| # | รายการ | วิธีตรวจ |
|---|---|---|
| จ1 | ตำแหน่งตัดในเกมตรงรอยคำชุดเดียวกับ CLI | จับข้อความจากเกม 3–5 ชุด → รัน `dotnet run --project src/ThaiWrap.Cli -- -m sep` กับข้อความเดียวกัน → เทียบว่าจุดขึ้นบรรทัดในเกมตกที่ขอบคำชุดเดียวกับที่ CLI แยก |

### ฉ. เสถียรภาพ + config กลางเกม

| # | รายการ | วิธีตรวจ |
|---|---|---|
| ฉ1 | เล่นต่อเนื่อง 15–30 นาที ไม่ crash / fps ไม่ตกผิดปกติ | เดินเล่นผ่านฉากข้อความหลายฉาก |
| ฉ2 | `Enabled=false` กลางเกม → ข้อความเดินหน้าเป็นของเดิม (ไม่ตัด) | แก้ `BepInEx/config/thaiwrap.plugin.cfg` ระหว่างเกม |
| ฉ3 | เปลี่ยน `Segmentation.Normalize=true` กลางเกม → reload พจนานุกรมสำเร็จตาม log | ดู log ข้อความ `โหลดพจนานุกรมใหม่` |
