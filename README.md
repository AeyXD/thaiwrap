# thaiwrap

[![CI](https://github.com/AeyXD/thaiwrap/actions/workflows/ci.yml/badge.svg)](https://github.com/AeyXD/thaiwrap/actions/workflows/ci.yml)

ทำให้ข้อความไทยในเกมตัดบรรทัดถูกจุด — **โดยไม่ต้องแก้เกมเลย**

ภาษาไทยเขียนโดยไม่เว้นวรรคระหว่างคำ แต่เอนจินเกมส่วนใหญ่ตัดบรรทัดที่ "ช่องว่าง" เท่านั้น
ผลคือข้อความไทยในเกมถูกตัดกลางคำ หรือยืดยาวล้นกรอบ

thaiwrap แก้ที่ตัวข้อความ: ตัดคำด้วยพจนานุกรมแล้วแทรก **จุดตัดบรรทัดที่มองแทบไม่เห็น**
ไว้ที่รอยต่อระหว่างคำ เอนจินเกมจะตัดบรรทัดตรงจุดนั้นเองโดยอัตโนมัติ

```
"กระบี่อันเป็นเลิศ" → ตัดคำ → กระบี่|อัน|เป็น|เลิศ → "กระบี่​อัน​เป็น​เลิศ" (แทรกจุดตัด)
```

ใช้ได้ 2 วิธี: **แก้ไฟล์งานแปลล่วงหน้า** ด้วยโปรแกรมบรรทัดคำสั่ง (CLI) หรือ **แก้ตอนเกมกำลังรัน**
ด้วยปลั๊กอิน BepInEx สำหรับเกม Unity — เลือกวิธีที่ตรงกับเกมและ workflow ของคุณ

## คุณสมบัติ

**ตัดคำแม่น**
- พจนานุกรม 65,758 คำ (รวมศัพท์จาก pythainlp + ICU thaidict) + อัลกอริทึม DP optimal segmentation
- คุณภาพจุดตัดเทียบเครื่องมือมาตรฐาน newmm: **precision 1.000** (จุดที่ตัด ไม่เคยตัดผิด)
  recall 0.773, F1 0.872 บนชุดประโยคเกมที่วัด — *ตัวเลขจากชุดตัวอย่างเพื่อเปรียบเทียบ
  อัลกอริทึม ไม่ใช่การรับประกันทุกข้อความ*
- เพิ่มคำเฉพาะของเกม/โปรเจกต์ได้เอง โดยวางไฟล์ `words_extra.txt` (ดูหัวข้อด้านล่าง —
  ชื่อตัวละคร ศัพท์ในเกม แย่งพยางค์ จัดการที่ระดับโปรเจกต์ ไม่ปนกับ dict กลาง)
- คำนอกพจนานุกรม (ชื่อเฉพาะ ชื่อตัวละคร) ไม่ถูกตัดแตก — แต่ถ้ายาวเกินไปจะได้จุดตัด
  ระดับก้อนพยางค์ กันข้อความล้นกรอบสี่เหลี่ยมของเกม
- ผ่านการใช้จริง: อัลกอริทึมต้นฉบับใช้กับซับไทย The Witcher 3 ([ThaiW3Setup](https://github.com/AeyXD/ThaiW3Setup))
  และ The Witcher 1 ([ThaiW1Setup](https://github.com/AeyXD/ThaiW1Setup))

**ไม่ทำลายไฟล์งานแปล** — หลักการใหญ่ของโปรเจกต์คือ "อนุรักษ์ของเดิม"
- นอกเหนือจากจุดตัดที่แทรก **ส่วนอื่นของไฟล์คงเดิมทุกไบต์**: การขึ้นบรรทัด (CRLF/LF),
  BOM, คอลัมน์ ID/ชื่อไอเทม, โครงสร้าง JSON, คอมเมนต์ใน .po
- **ดูก่อนทำจริงเสมอ**: `--dry-run` แสดง diff ของทุกบรรทัดก่อนเขียนอะไรลงไฟล์
- **สำรองอัตโนมัติ**: โหมดเขียนทับ (`--inplace`) สร้าง `.bak` ตั้งแต่รอบแรก และจะไม่ทับ
  ไฟล์สำรองเดิมเมื่อรันซ้ำ · โหมดปกติเขียนเป็นไฟล์ใหม่ `ชื่อ.zwsp.ext` ไม่แตะต้นฉบับ
- **ปกป้องโค้ดของเกม**: `{placeholder}` เช่น `{ชื่อผู้เล่น}` และแท็ก rich-text
  `<color=red>…</color>`, `<link="…">` ไม่ถูกแทรกจุดตัดเด็ดขาด แม้ข้างในมีตัวอักษรไทย —
  ไม่งั้นการแทนค่าตอนรันของเกมจะพัง
- รันซ้ำกับไฟล์ที่แปลงแล้ว ไม่เพิ่มจุดตัดซ้ำ (idempotent — ยกเว้นโหมด space ด้านล่าง)
- การเข้ารหัสไฟล์ผิดจะถูก**ปฏิเสธ** (เช่น CP874 ไม่มี BOM) ไม่ใช่แปลงเงียบๆ จนตัวอักษรเสีย

**รองรับไฟล์งานแปล 5 แบบ** — ดูรายละเอียดและวิธีเลือกไฟล์/คอลัมน์ที่หัวข้อ "ไฟล์งานแปลที่รองรับ"

**โหมดตรวจสำหรับ pipeline** (`--check`) — ไม่เขียนอะไร exit 1 ถ้ายังมีข้อความไทยที่ไม่ถูกแตรป ·
ติดเป็น pre-commit หรือช่วง CI ของทีมแปลได้เลย เพื่อกันไฟล์แปลเดินเข้าเกมโดยยังไม่ผ่านการตัดคำ

**ตรวจ "วางคำแปลผิดแถว"** (`--mispaste`) — ทีมแปล copy ข้อความของแถวอื่นมาวาง ทำให้คำแปลไม่ตรง
ต้นฉบับและจุดตัดผิดทั้งแถว**โดยเงียบ** · ตรวจจากคู่อังกฤษ-ไทยใน csv/tsv (ไทยซ้ำกัน ≥40 ตัวแต่อังกฤษ
ต่างเรื่อง · ความยาวไทย/อังกฤษนอกช่วง 0.2–3.5) เกณฑ์พิสูจน์แล้วบนคลังจริง (จับ 31/31 ใน W3) ·
**เป็นข้อเสนออย่างเดียว** ตรวจด้วยตาก่อนแก้ที่ต้นทาง

**แก้คำพิมพ์ผิดก่อนตัดคำ** (`--normalize`) — ข้อความไทยจริงจากทีมแปลมักมีรูปพิมพ์ผิด
ที่โปรแกรมแสดงผล "ดูถูกต้อง" จนคนตาไม่เห็น แต่ทำให้ตัดคำพลาดทั้งย่อหน้า เช่น
`เเ` แทน `แ` (เเท้), สระ/วรรณยุกต์ซ้อน (สวััสดี), `นํ้า` ที่จริงคือ `น้ำ` — เปิดใช้ด้วย
`--normalize` (ปิดไว้เป็น default เพราะแก้ตัวอักษรจริง)

**ครอบคลุมเกม 3 ตระกูลเอนจิน** — เลือกโหมดตามตารางด้านล่าง (ZWSP / hairspace / ช่องว่างจริง)

**ไม่ต้องติดตั้งอะไรเพิ่ม** — ตัวโปรแกรมเป็นไฟล์เดียวรันได้เลยทั้ง Windows, macOS, Linux
(อยู่ที่ [publish/](publish/) ใน repo) ไม่มี dependency ไม่ต้องมี .NET ในเครื่อง ·
ส่วนคนอยากแก้โค้ด ใช้ `dotnet` รันจากซอร์สได้ทันที

| **RPG Maker MZ** | ตัดระดับตัวอักษร | ZWSP ไม่ช่วย — ต้องแก้ที่ plugin จัดการตัดบรรทัดเอง |

### โหมด `--break-char space` (เอนจินที่ตัดเฉพาะช่องว่างจริง)

บางเอนจินตัดบรรทัดเฉพาะช่องว่างจริงตัวเดียว ทางเลือกเดียวคือเว้นวรรคจริง — แต่ถ้าเว้น
ทุกคำ ข้อความจะอ่านเหมือน "เว้น วรรค ทุก คำ" thaiwrap จึง**รวมคำเป็นกลุ่มวลี** (DP + กฎ
ผูกคำไทย: ไม่เว้นหลัง ผู้/การ/ใน/ไม่ ไม่เว้นก่อน ได้/แล้ว/ไป) แล้วเว้นเฉพาะรอยต่อกลุ่ม:

```
นักผจญเหตุการณ์วิเศษพาเพื่อนๆเดินทางข้ามป่าลึกเพื่อตามหาสมบัติโบราณที่สาบสูญมานานหลายร้อยปี
→ นักผจญ เหตุการณ์ วิเศษพา เพื่อนๆเดิน ทางข้ามป่าลึก เพื่อตามหา สมบัติโบราณ ที่สาบสูญมา นานหลายร้อยปี
```

- ค่า default เมื่อเลือก space: กลุ่มยาวไม่เกิน 12 ตัวอักษร (`--chunk`) · ข้อความสั้นกว่า
  40 ตัวอักษรไทยไม่ถูกแตะ กัน "เกม ใหม่" กลางป้ายเมนู (`--min-len`)
- แทรกเฉพาะรอยต่อคำไทยด้วยกัน ไม่แตะรอบตัวอักษรอังกฤษ/เครื่องหมาย
- **ไม่ idempotent** (ช่องว่างที่แทรกแยกจากช่องว่างของทีมแปลไม่ได้) — รันจากต้นฉบับสะอาด
  หรือ `--dry-run` ก่อนเสมอ
- พอร์ตจาก [ThaiW1Setup](https://github.com/AeyXD/ThaiW1Setup) ซึ่งพิสูจน์ในเกมจริง (Witcher 1)
  พร้อมเทคนิคเสริมระดับฟอนต์: ย่อความกว้างช่องว่างเหลือครึ่งเดียวให้แทบมองไม่เห็น —
  วิธีเต็มที่ [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md)

## ใช้งาน CLI

```bash
cd thaiwrap
export PATH="$HOME/.dotnet:$PATH" DOTNET_ROOT="$HOME/.dotnet"   # ถ้ารันจากซอร์ส

# ดูผลตัดคำเป็นคำๆ (ทดลองเล่น)
dotnet run --project src/ThaiWrap.Cli -- samples/game_sentences.txt -m sep | head

# ไฟล์งานแปล — workflow ปลอดภัย: ดู diff ก่อน แล้วค่อยเขียนไฟล์ใหม่
dotnet run --project src/ThaiWrap.Cli -- tests/samples/items.csv --columns thai --dry-run
dotnet run --project src/ThaiWrap.Cli -- tests/samples/items.csv --columns thai -o /tmp/items.out.csv
dotnet run --project src/ThaiWrap.Cli -- data/ -r                 # ทั้งโฟลเดอร์ → สร้าง *.zwsp.*
dotnet run --project src/ThaiWrap.Cli -- th.txt -f keyvalue -o th.out.txt
```

(ถ้าใช้ binary จาก `publish/` แทน `dotnet run ... --` ด้วยชื่อไฟล์โปรแกรมตรงๆ เช่น
`./ThaiWrap.Cli tests/samples/items.csv --columns thai --dry-run`)

Options หลัก: `-f auto|text|csv|tsv|json|po|keyvalue` · `--columns "1,3" หรือ "ชื่อ"` · `--json-keys "desc,tooltip"` · `--break-char zwsp|hairspace|space` · `--chunk <n>` · `--min-len <n>` · `--normalize` · `--dry-run` (diff, ZWSP แสดงเป็น ·) · `--mispaste` (ตรวจวางผิดแถว) · `--check` (lint สำหรับ CI) · `-r` · `--inplace` (+.bak) · `--maxword` (0=ไม่จำกัด) · `--unknown-threshold` · `--stats`

## ไฟล์งานแปลที่รองรับ

ทุกแบบใช้หลักการเดียวกัน: **อ่านไฟล์ แปลงเฉพาะข้อความภาษาไทย เขียนกลับโดยส่วนอื่นคงเดิม** —
ไม่ต้องแปลงไฟล์เป็นฟอร์แมตอื่นก่อน และทีมยังเปิดแก้ต่อด้วยเครื่องมือเดิมได้

| รูปแบบ | คือไฟล์อะไร | ตรวจสอบความปลอดภัย |
|---|---|---|
| **CSV / TSV** | ตารางข้อความ (เปิด/แก้ใน Excel ได้ · TSV คั่นด้วยแท็บ) | default แปลงทุกคอลัมน์ — ถ้ามีคอลัมน์ ID/รหัส ใช้ `--columns` เลือกเฉพาะคอลัมน์ไทย |
| **JSON** | ข้อความซ้อนหลายชั้น (setting, dialog tree) | key ไม่ถูกแตะเสมอ · ถ้ามี value ที่เป็นรหัส ใช้ `--json-keys` เลือกเฉพาะ field ข้อความ |
| **PO / POT** | ไฟล์แปลมาตรฐาน gettext (นักแปลซอฟต์แวร์ใช้ทั่วไป) | แปลเฉพาะคำแปล (msgstr) — ข้อความต้นทาง (msgid), header, รายการเก่า (#~) ไม่ถูกแตะ |
| **key=value** | รูปแบบ XUnity.AutoTranslator (`ข้อความเดิม=คำแปล`) | ระบุ `-f keyvalue` — คีย์และคอมเมนต์ไม่ถูกแตะ |
| **ข้อความเปล่า** (.txt) | บรรทัดละข้อความ | default · อ่านจาก stdin ได้ด้วย |

รูปแบบไม่ต้องระบุก็ได้ — โปรแกรมเดาจากนามสกุลไฟล์อัตโนมัติ (`-f auto`)

## เพิ่มคำศัพท์เฉพาะเกมเอง — วางไฟล์ `words_extra.txt`

พจนานุกรมกลางมีคำไทยทั่วไป แต่ทุกเกมมีศัพท์เฉพาะของตัวเอง (ชื่อตัวละคร สถานที่ อาชีพในเกม) — เพิ่มเองได้โดย**วางไฟล์ชื่อ `words_extra.txt`** ไว้ที่นี่ (เจออันแรกเจอก่อน):

- โฟลเดอร์ที่รันคำสั่ง หรือ `data/words_extra.txt`
- ข้างไฟล์ `words_th.txt` (รวมโฟลเดอร์ `BepInEx/plugins/ThaiWrap/` ของปลั๊กอิน)
- ข้างตัวโปรแกรม (binary ที่แจก)

ไม่ต้องใส่ option ใดๆ — มีไฟล์เมื่อไหร่ใช้เลย และจะขึ้นรายงานให้เห็นว่าโหลดอะไรไป (+เพิ่ม −ลบ กี่คำ)

```text
# คำอธิบายขึ้นต้น # ก็ข้าม
เฟรย่า            ← บรรทัดธรรมดา = เพิ่มคำ (ชื่อตัวละคร ศัพท์เกม)
-ใช้การ           ← ขึ้นต้น - = ลบคำออกจากพจนานุกรม
```

การ**ลบ**สำคัญเท่าการเพิ่ม: บางคำใน dict กลาง "แย่งพยางค์" คำถัดไปจนตัดผิด เช่น `ใช้การเล่น` โดนตัดเป็น `ใช้การ|เล่น` — ลบ `ใช้การ` ออกกลับเป็น `ใช้|การ|เล่น` (เคสจริงจาก Witcher 1)

**รู้ได้ยังไงว่าควรเพิ่มคำไหน**: รันด้วย `--stats` แล้วดูท้ายรายงาน — มีส่วน "คำนอกพจนานุกรมที่พบบ่อย" เรียงตามความถี่ให้เลย (เช่น `วิท ×5755 · เอลฟ์ ×570 · รอบๆ ×567`) คัดเอาอันที่เป็นคำจริง/ใช้ซ้ำบ่อยใส่ `words_extra.txt` — อย่าเพิ่มชื่อเฉพาะของเกมลง dict กลาง (`data/words_th.txt` ส่วนรวม) เพราะจะไปกระทบโปรเจกต์อื่น

## แก้คำพิมพ์ผิดก่อนตัดคำ — `--normalize`

ข้อความไทยจากทีมแปลจริงมักมีรูปพิมพ์ผิดที่ **editor และ Excel render ให้ดูถูกต้อง**
จนสายตาคนไม่เห็น แต่โปรแกรมตัดคำอ่านไม่ออก แล้วจุดตัดเพี้ยนทั้งย่อหน้า ไม่ใช่แค่คำนั้น:

```
ก่อน --normalize:  สวัั·สดี·เป็็็น·ทาส     (พังทั้งวลี)
หลัง --normalize:  สวัสดี·เป็น·ทาส
```

กฎทั้งหมดมาจากสิ่งที่**เจอจริง**ในคลังแปล production 176,230 ข้อความ (Witcher 3) และแก้เฉพาะ
รูปที่เป็นไปไม่ได้ทางภาษาไทยจึงมีทางแก้เดียว: `เเ→แ` · สระ/วรรณยุกต์ซ้อน (สวััสดี) ·
ลำดับมาร์คผิด (มาท่ีนี่) · `นํ้า`→`น้ำ` · วรรณยุกต์หลง (ไ่ม่→ไม่) — ส่วนรูปที่กำกวมต้องตัดสินใจ
(เช่น สระต่างตัวซ้อน ิี) จะ**เตือนใน `--stats` ให้กลับไปแก้ที่ต้นทาง** ไม่แก้เอง ·
ไม่แตะ า ลากเสียง/พยัญชนะซ้ำ (อาาา ฮั่กกกก) · placeholder และแท็กไม่ถูกแตะ ·
เป็นการแก้ตัวอักษรจริง จึง default ปิด

## ใช้ตอนเกมรันด้วย BepInEx (Unity)

สำหรับเกม Unity ที่ติด BepInEx 5 ได้ — ปลั๊กอินจะ hook ตอนข้อความถูกแสดงผล ตัดคำให้ทันที
ไม่ต้องแก้ไฟล์ล่วงหน้า:

- รองรับ TextMeshPro และ UGUI Text (ค้นหา component ตอนรัน — DLL เดียวใช้ได้หลายเกม)
- มี cache ไม่ตัดคำซ้ำเมื่อเกมวาดข้อความเดิมทุกเฟรม · ปลอดภัยกับเอฟเฟกต์พิมพ์ทีละตัว
- ปรับการตั้งค่าได้กลางเกม (เปิด/ปิด, normalize, ความยาวคำ) ที่ `BepInEx/config/`
- ใช้ `words_extra.txt` คำเฉพาะเกมได้เหมือน CLI — วางข้าง `words_th.txt` ในโฟลเดอร์ปลั๊กอิน
- แพ็กพร้อมติดตั้ง + คู่มือไทย: `./tools/package-plugin.sh` → `dist/ThaiWrap/`
- ยังไม่รองรับเกม IL2CPP (BepInEx 6)

## อัลกอริทึมตัดคำ (สำหรับสายเทคนิค)

**DP optimal segmentation** — หาการตัดคำที่ minimizes (จำนวนตัวอักษรนอกพจนานุกรม, จำนวนคำ)
ภายใต้กฎพยัญชนะทวิภาคของไทย (ห้ามแยกสระ/วรรณยุกต์ออกจากพยัญชนะ ห้ามทิ้งสระหน้าท้ายบรรทัด
ห้ามตัดก่อน ๆ/ฯ)

- port จาก [ThaiW3Setup](https://github.com/AeyXD/ThaiW3Setup) (`core/thai_wrap.py`, MIT) ซึ่งใช้จริงใน
  production กับซับไทย The Witcher 3 · ตรวจสอบการ port: output ตรงต้นฉบับ Python เป๊ะ 41/42 ประโยค
  (ตัวที่ต่างคือเคส `{placeholder}` ที่ thaiwrap ปกป้องทั้งก้อนโดยเจตนา)
- โหมด space ใช้ DP ชั้นที่สอง (กลุ่มวลี) พอร์ตจาก [ThaiW1Setup](https://github.com/AeyXD/ThaiW1Setup) (MIT)
- โครงสร้างโค้ด: `src/ThaiWrap` (core, ตัดคำ+กฎผูกคำ+normalize) · `src/ThaiWrap.Formats`
  (อ่าน/เขียน 5 ฟอร์แมตแบบอนุรักษ์เดิม) · `src/ThaiWrap.Cli` · `src/ThaiWrap.BepInEx` —
  core และ plugin เขียนด้วย API เก่าๆ ที่มีในทุก.NET ไม่มี dependency ภายนอกทั้งโปรเจกต์
- เทส 118 ข้อ (invariant + ประโยคเกมจริง + ทุกฟอร์แมต + ความปลอดภัยไฟล์ + normalize + กลุ่มวลี) ·
  CI รันบน ubuntu + windows จริง รวมทดสอบ binary ที่แพ็กแล้ว

## กฎความปลอดภัยของการแทรกจุดตัด

- ไม่แทรกก่อนสระ/วรรณยุกต์ที่ประกอบกับพยัญชนะก่อนหน้า (ั ิ ี ึ ื ุ ู ็ ่ ้ ๊ ๋ ํ ๎)
- ไม่แทรกหลังสระหน้า (เ แ โ ใ ไ) ที่ยังไม่มีพยัญชนะตาม
- ไม่แทรกก่อน ๆ (ไม้ยมก) และ ฯ (ไปยาลน้อย)
- ไม่แทรกทั้งช่วง `{placeholder}` และแท็ก rich-text `<...>` (ปิดได้ด้วย option `ProtectPlaceholders`)
- ไม่แทรกติดช่องว่างเดิม, ต้น/ท้ายข้อความ, ก่อนเครื่องหมายปิด หรือหลังเครื่องหมายเปิด
- ตัวเลข/อังกฤษ (`25%`, `150/200`, `XP`) คงเป็นก้อนเดียว
- ชื่อเฉพาะ/คำนอกพจนานุกรมที่สั้นกว่า 8 cluster ถือเป็นก้อนเดียว ยาวกว่านั้นจึงยอมให้ตัด
  ระดับ cluster (กันล้นกรอบ)
